## 1. 修复目标

## 2. 文档权威规则

发生文档冲突时，按以下优先级判断：

1. **仓库实际代码与 Git 历史**：判断功能是否存在、文件是否提交、代码变动范围。
2. **对应 GitHub Actions 运行及测试记录**：判断 CI、JVM 单元测试、Android 测试源码编译、APK 组装与 Artifact 上传是否成功。源码编译不得描述成模拟器 / 真机执行；真机验收必须有用户确认或明确设备记录。
3. **`docs/IMPLEMENTATION_STATUS.md`**：唯一的当前进度账本。只在这里维护当前阶段、已完成项、未完成项、最新构建与下一步；详细历史按阶段追加，不覆盖或删除旧记录。
4. **专项规划文档**：定义目标、架构、约束、依赖和验收条件；除明确标注的历史快照外，不自行维护滚动的“当前进度”。实际状态引用进度账本。
5. **`README.md`**：对外摘要、最新成功构建入口和文档导航；不复制大段实施账本。
6. **`docs/PROJECT_STATUS_AND_GUIDE.md`**：只讲如何接手、开发、构建、排错和验收；不维护独立的当前阶段或当前任务结论。

聊天中的旧信息、过期文档快照和历史提交说明都不能覆盖当前代码与可验证的构建事实。若两项高优先级证据冲突，先调查，不猜测。

## 4. 阶段路线映射的设计原则

编号体系不会被强行合并为一个编号，也不要求一对一映射。

- **C0–C12**：计算器数学 / 工具 domain 与主计算页接入路线。
- **P0**：全局产品策略和约束，不是代码步骤。
- **Q1–Q4**：题目文档、编辑器、专用键盘及符号输入路线，可在不依赖未完成 solver 的前提下先做模型设计 / 编辑器基础。
- **M1**：数学底座总括，与 C0–C6 及后续数学扩展重叠，不是额外一轮独立重复实现。
- **S1–S2**：题型识别、能力注册表和高中题型扩展；具体依赖对应 parser / domain solver。
- **G1**：函数求值、定义域与 C7 domain；**G2–G3**：自适应绘图、视口及交互 UI。
- **C8**：单位目录、转换内核和独立单位工具页面；不等同于 C12 主计算器页面。
- **S3**：化学 / 物理专项迁移，大体对应 C9–C10 的化学部分并扩展物理模型。
- **C11**：本地计算历史与持久化。
- **C12**：最小主计算页面，按已经完成的 domain 能力逐项接入。
- **AI-0–AI-4**：复杂度判断、Worker 移动端安全、网络层和 AI 交互；AI 网络安全前置条件不能被其他阶段绕过。
- **R1**：键盘、图像、AI 面板和主壳的综合真机体验验收。

映射表会注明共享依赖与可并行工作，不能把上表理解为所有路线必须严格串行。

## 6. 仓库维护规则

1. 普通功能提交不得顺手删除 `docs/` 中仍被引用的文件。
2. 删除 / 改名文档时，必须同一步更新所有本地链接、README 导航和相关专项文档，并让链接检查通过。
3. 不得把外部仓库文件写成当前仓库可解析的相对路径；使用 `仓库名:路径` 或完整 GitHub URL。
4. 当前进度只在 `IMPLEMENTATION_STATUS.md` 维护；其他文件只引用账本，不复制不断变化的构建状态。
5. 历史段落可保留，但必须明确其日期和“历史快照”属性，不能再作为当前任务入口。
6. 每个阶段独立提交，并在本计划中记录提交 SHA 和验收结果。文档专用提交可使用 `[skip ci]`；校验脚本 / workflow 变更必须运行对应 CI。
