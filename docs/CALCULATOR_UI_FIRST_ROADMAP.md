## 0. 前置阶段：先重建 UI 框架

本路线的 UI-0–UI-10 不直接在现有页面结构上执行。必须先完成 UI 框架的 F0–F7：现状审计、Zhixing Flow Tokens、组件库、整页式边界回弹、App Shell / 导航重建、逐页迁移与整体性能验收。

其中最重要的滚动交互规则是：禁止页面内容橡皮筋式拉伸；触及顶部 / 底部边界时，由整个内容视口作为刚性整体产生有限位移，松手后通过统一弹簧回到边界。浮动 Dock 与系统栏固定不动。实现细节见 [ZHIXING_DESIGN_SYSTEM_REBUILD_PLAN.md](./ZHIXING_DESIGN_SYSTEM_REBUILD_PLAN.md) §5。

## 1. 本次路线调整的决定

### 1.1 明确改变顺序

此前采用了较长时间的“数学题型逐项扩展，最后集中接 UI”方式。它能让算法逐步积累，但当 C5 不断出现新的 C5.x 时，产品始终缺少一个可完整使用的计算器主页面，阶段边界也变得不清晰。

从本规划开始，停止把新增求解器编号当作默认下一步。执行顺序改为：

0. 先完成 Zhixing Flow 框架 F0–F7；框架重建期间不扩展新的数学题型。

1. 盘点并稳定现有 UI、domain、导航和工具页面接口。
2. 优先开发计算器主页面、表达式编辑、应用内键盘、结果展示和工具页面。
3. 将已经完成并通过 CI 的数学能力逐项接入界面。
4. 对暂不支持的题型提供明确、诚实的“不支持”状态，不伪装成“无解”或错误答案。
5. 界面流程和接入架构稳定后，再按照高中题型覆盖矩阵批量补齐数学能力。
6. 每次新增数学能力只需接入既有页面 / solver adapter，不重新设计整套交互。

### 1.2 冻结当前数学扩展队列

- C5.18 是本轮已完成的阶段边界。
- C5.19（例如 `cos(ax+b)=cos(cx+d)`）及其他新方程变体暂缓，不作为当前入口。
- 暂缓不代表永久放弃；未来只有当题型覆盖矩阵确认其优先级，或实际页面接入暴露出必要缺口时，才建立明确的小批次任务。
- 不再为了让编号连续而开发低优先级变体。
- 现有 C0–C8 内核继续保留、维护和复用，不重写已经验证的算法。

### 1.3 为什么现在可以转向界面

当前已有的基础包括：

- C0–C4：词法分析、表达式解析、常数求值、多项式与有理函数基础、定义域和部分实根。
- C5.1–C5.18：多类多项式 / 分式 / 绝对值 / 根式 / 指数对数 / 三角方程，以及二元一次方程组和周期解筛选。
- C6.1–C6.2：一至三次多项式不等式与分式不等式。
- C7.1–C7.6：坐标点校验、一次 / 二次 / 三次 / 反比例拟合、定义域、求值和安全采样。
- C8.1–C8.7：单位目录、单位定义、统一转换与旧版兼容回归。
- C8.8.1–C8.8.2：独立单位换算原生页面已有首版和交互完善记录；真机验收仍按状态账本单独记录。

这些成果足以支撑首轮可用界面。不能因为尚未覆盖完整高中数学，就继续推迟 UI。

## 2. 目标产品与阶段完成定义

### 2.1 第一目标：先得到可使用的计算器

第一轮界面阶段结束时，用户应能完成一条真实的端到端流程：

- 打开「计算」，立即看到可输入的计算工作区，不被介绍卡片或空白占位阻挡。
- 使用应用内键盘输入普通算式；能编辑光标位置、插入、删除、清空和计算。
- 结果区能区分输入中、结果成功、输入未完成、表达式错误、定义域错误和当前能力不支持。
- 标准 / 科学模式共用稳定的表达式编辑区与基础键盘布局。
- 进入工具目录，打开已实现的方程、不等式、函数和单位换算页面。
- 对已经支持的题型得到本地结果；对未支持的题型得到明确解释和可用的后续处理入口。
- 返回页面时，当前输入和必要的 UI 状态不无故丢失。
- 基础功能无需登录、无需网络即可使用。

### 2.2 第一轮界面阶段不代表数学能力已经完整

界面阶段结束时，不能宣称“高中数学全部支持”。它表示输入、交互、结果、错误、路由和页面结构已经具备，后续只需扩充 domain 能力并接入统一结果组件。

### 2.3 功能状态必须区分

统一使用以下结果状态，不允许互相混用：

| 状态 | 含义 | UI 呈现 |
|---|---|---|
| Success | 当前 solver 给出通过校验的结果 | 展示答案、集合 / 图像 / 过程摘要 |
| IncompleteInput | 用户仍在输入，表达式尚未闭合 | 轻量提示，不显示成数学错误 |
| InvalidInput | 输入语法不合法或字段格式错误 | 指出位置和可修复原因 |
| DomainError | 输入违反定义域或原式约束 | 明确指出除零、真数、根式等约束 |
| NoSolution | 当前模型可证明无解 | 明确展示“无解”及必要原因 |
| InfiniteSolutions | 当前模型可证明有无穷多解 | 展示全体实数或对应解集 |
| Unsupported | 题型、次数、结构或条件超出当前实现范围 | 显示“不支持此题型 / 当前范围”，不得显示“无解” |
| NumericFailure | 溢出、下溢、精度损失或非有限中间值 | 显示数值范围 / 精度限制，不给伪造数值 |
| Cancelled | 用户取消或页面输入变化导致旧任务失效 | 安静结束旧任务，不覆盖新输入 |

UI 只负责呈现；状态的判定来源是 domain / adapter 的明确结果，不通过检查错误文案或猜测空列表来推断。

## 3. 页面结构与导航边界

### 3.1 一级导航维持现有结构

继续使用已经建立的四个一级入口：

1. **计算**：标准 / 科学计算工作区。
2. **知行 AI**：独立的 AI 对话入口；不把常驻聊天框塞进计算键盘上方。
3. **工具**：方程、不等式、函数、单位换算等独立工具入口。
4. **我的**：本地历史、材质和应用设置。

本轮不重做已验收的底部 Liquid Glass Dock，也不重新拆分主壳导航。页面内容和二级路由应适配现有主壳。

### 3.2 工具目录按真实能力开放

- 工具目录只显示已实现并可进入的页面。
- 已完成单位换算页面继续保留。
- 方程、不等式、函数页面完成首版 UI 和对应已有能力接入后，再作为可用入口稳定展示。
- 化学配平、反应预测和物理工具暂不放置会让用户误以为可用的入口；待对应界面和最小真实能力同时具备后再开放。
- 暂未支持的某个题型，可以在已开放的通用 solver 页面中显示 Unsupported；不要把整个页面伪装成已完成。

### 3.3 页面之间的职责

| 页面 | 负责什么 | 不负责什么 |
|---|---|---|
| 计算主页 | 普通表达式输入、即时预览、计算、标准 / 科学模式 | 完整题目识别、所有方程求解、AI 对话 |
| 方程页 | 方程输入、变量 / 条件设置、求解、解集与验证摘要 | 自行实现求根算法 |
| 不等式页 | 不等式输入、区间条件、解集展示 | 在 UI 中进行符号区间算法 |
| 函数页 | 函数 / 点集输入、分析入口、图像与视口交互 | 在 Canvas 中执行解析或拟合 |
| 单位换算页 | 数值、源单位、目标单位、换算结果 | 复制换算常量或重写 UnitConverter |
| 历史页 | 本地记录搜索、筛选、恢复、删除 | 与 AI 云端对话混用同一数据源 |

## 4. 架构与接口约束

### 4.1 分层

继续保持单一 `:app` Gradle 模块，暂时不因页面增加而过早拆分多个 Gradle module。代码按职责组织：

- **domain**：Tokenizer、Parser、表达式 / 题目模型、solver、函数采样、单位换算和类型化结果；不依赖 Android、Compose、Activity 或 ViewModel。
- **data**：本地历史读写、设置持久化，以及未来需要的远程数据适配。
- **presentation / ui**：Compose Screen、ViewModel、UI State、用户事件、输入键盘和图表绘制。
- **navigation**：页面目的地、参数传递、返回栈和状态恢复。
- **design system**：现有 Zhixing Theme、Backdrop、Liquid Glass surfaces、按钮、键帽、输入面板、结果面板等可复用组件。

不要把 Parser、solver、数值采样、数据库读写、网络请求放到 Activity 或大型 Composable 中。

### 4.2 主计算页最小接口

计算页 ViewModel 至少提供：

- 当前表达式 / 编辑文本。
- 当前光标与选区信息（由编辑器状态承载）。
- 标准 / 科学模式。
- 计算状态：空、编辑中、预览成功、最终成功、输入不完整、错误、不支持。
- 格式化后的主要结果与必要的原始数值。
- 输入事件：插入文本 / token、退格、清空、移动光标、替换选区、计算、复制。
- 任务代次或输入版本号，用于丢弃过期预览 / 求值结果。

用户每次输入不应启动一个无法取消且会覆盖最新结果的后台任务。快速连续输入时，旧结果不能在新结果后面闪回。

### 4.3 统一 Solver 入口

方程、不等式、函数工具不要直接依赖某个具体 C5.x 类。建立薄的注册 / 适配层：

- 输入：题型、表达式 / 结构化参数、变量、区间 / 条件。
- 输出：统一的 Typed Outcome。
- 每个 solver 声明支持的题型、次数、输入结构和已知限制。
- 已支持题型路由到现有 C5 / C6 / C7 实现。
- 未命中能力时返回 Unsupported，附带用户可理解的能力范围。
- 不得把 Unsupported、解析失败、数值错误或 NoSolution 合并成一个空结果。

注册层只负责识别、路由和结果映射，不复制具体数学逻辑。

### 4.4 表达式编辑与输入事件

- UI 输入层保留用户可见的原始表达式；Parser 负责归一化与语法结构。
- 键盘按钮输出明确 token / 编辑操作，不直接拼接复杂的数学渲染字符串。
- 括号、分数、根式、上下标等复杂模板后续通过编辑事务实现。
- 每次模板插入、删除或替换必须保持光标位置确定。
- 输入未完成与非法表达式必须分开表示。
- 默认应用内键盘；系统键盘作为主动切换选项，允许输入中文题干、复制粘贴和长文本。

### 4.5 数学结果与显示隔离

- 数值格式化、有效数字、科学计数法和负零处理集中管理。
- UI 不自行根据浮点值拼答案。
- 解集、周期解族、区间端点、定义域排除点等信息必须保持结构化，不能先转成一段字符串再做筛选。
- 过程展示先显示可信的步骤摘要；没有可靠推导数据时，不伪造详细推导。
- 表达式文本和答案区域关闭会扭曲符号的折射 / 色散，保障可读性。

## 5. 第一阶段：原生界面优先

本阶段不增加新的数学求解器题型。允许进行必要的接口适配、状态封装和显示格式化，但不借此扩展新的算法范围。

### UI-0：代码与页面基线盘点

**目标：** 找到现有主壳、导航、单位页面、主题和测试入口，明确复用点，避免重复造轮子。

工作项：

- 核对 MainActivity / AppRoot / 导航图 / 页面状态管理的实际位置。
- 核对现有「计算」「工具」「我的」入口和二级页面动画。
- 核对 C0–C8 domain 类、模块包名、输入类型、typed error 和测试入口。
- 核对单位换算 Compose 页面，列出可复用输入、选择器、结果、复制、无障碍组件。
- 核对 Backdrop / Glass 组件的实际 API，确认哪些适合键盘、结果面板和小控件。
- 绘制页面路由图与 domain 调用图；列出真实文件路径，不能仅按规划猜文件结构。
- 形成 UI State / ViewModel / Solver adapter 的接口草案。

交付：

- 页面与路由清单。
- 现有 domain 能力到 UI 的映射表。
- 需要新建 / 复用的组件清单。
- UI-1 的最小改动范围。

验收：

- 不改动已经验收的导航和玻璃组件行为。
- 不复制 domain 算法。
- 不因基线盘点把当前可用工具入口破坏。
- 文档里的文件位置与仓库实际结构一致。

### UI-1：计算主页骨架与标准模式

**目标：** 把「计算」变成真正的主计算器页面，打开后就可以输入。

页面组成：

1. 顶部轻工具栏：标题、标准 / 科学模式切换和必要的编辑操作；不放大幅 Hero。
2. 表达式编辑区：展示当前输入，支持基本光标与局部修改；长表达式在编辑区内部滚动。
3. 结果面板：为即时预览和最终结果提供稳定位置；空状态不占据过多高度。
4. 主数字键盘：四列五行，数字和基础运算符按拇指操作排序；退格放在编辑区附近。
5. 底部导航：沿用主壳当前玻璃 Dock 与安全区处理，不复制一套导航。

标准键盘的基线布局：

| 行 | 按键 |
|---|---|
| 1 | AC、括号、百分号、除号 |
| 2 | 7、8、9、乘号 |
| 3 | 4、5、6、减号 |
| 4 | 1、2、3、加号 |
| 5 | 正负号、0、小数点、等号 |

交互规则：

- 默认不自动弹出系统输入法。
- 按键按下即时反馈，松手短促恢复。
- 连续点按不丢字符、不重复、不因动画协程取消而漏输入。
- AC 清除当前表达式；退格删除光标前内容；有选区时优先替换 / 删除选区。
- 括号成对插入时光标落在内部；用户仍可修正单侧括号。
- 等号执行明确计算；预览值不能覆盖输入。
- 页面重组不得让键盘整体跳动，焦点变化不得突然滚动整页。

首轮接入只支持当前 Parser / evaluator 确实具备的语法。不得仅因为屏幕上画出了 sin、矩阵或积分键，就声称其数学功能已经可用。

验收：

- 普通四则、括号、负数、小数、幂和当前 Parser 支持的表达式可完整输入、修改和计算。
- 输入错误、空输入和未完成输入的状态区分正确。
- 360dp 左右窄屏、目标设备字体放大时不挤压触控区。
- 键盘点击区域舒适，误触率可通过真机连续输入检查。
- 计算逻辑仍由 domain 执行，UI 不含数学算法。

### UI-2：输入编辑与科学模式

**目标：** 在不破坏标准键盘布局的前提下，增加科学计算常用入口。

工作项：

- 标准模式保留基础数字 / 运算符布局。
- 科学模式增加可横向浏览的辅助函数条；不改变主键盘位置和大小。
- 只启用现有 Parser / evaluator 能解析的函数、常量和运算符。
- 未实现的符号暂不作为“可计算”按钮展示；可以通过后续扩展键盘规划预留位置，但必须有清楚的禁用 / 未支持说明。
- 提供角度 / 弧度设置时明确显示当前单位；现有弧度制 solver 不应在 UI 中悄悄按角度解释。
- 提供退格长按连删、光标移动、选区替换、复制 / 粘贴。
- 评估系统输入法主动切换，不强制禁止用户输入中文说明。
- 输入区域与键盘状态分离保存，旋转和页面切换后可恢复。

验收：

- 标准 / 科学切换不清空表达式、不重置光标、不改变底部 Dock 状态。
- 连续点击、长按退格、粘贴长表达式可正常工作。
- 输入未完成时不显示错误噪声。
- 无障碍可以朗读按键名称和模式状态。

### UI-3：结果展示、错误与复制

**目标：** 让用户看得懂“算出了什么、为什么失败、当前是否支持”。

工作项：

- 成功态：结果突出显示，输入仍可编辑。
- 预览态：输入变化后显示轻量预览；过期结果立即失效。
- 精确 / 近似态：明确标注近似值；保留原始数值与显示格式。
- 错误态：将解析错误、定义域错误、除零、非有限值、精度丢失分别映射到可理解的提示。
- Unsupported：显示不支持的题型或结构，并说明当前可用能力范围。
- 复制：可复制表达式、结果或完整等式；复制目标由用户明确选择。
- 复杂过程：首屏只展示答案与简短摘要，展开后再展示已有且可信的推导信息。

验收：

- NoSolution 与 Unsupported 不混淆。
- DomainError 与 InvalidInput 不混淆。
- 精度损失不展示成一个看似正常的零或无穷大。
- 输入发生变化后，旧结果不能被当成当前答案。
- 复制文本与界面当前表达式和结果一致。

### UI-4：工具目录与二级页面框架

**目标：** 让计算相关能力有清楚的入口和独立工作空间。

工作项：

- 工具 Tab 采用清晰、轻量的分组列表，不堆叠大面积运营卡片。
- 建立统一二级页面骨架：顶部标题 / 返回、主要输入、运行操作、结果区、帮助说明。
- 返回动画沿用现有主壳过渡；返回时保留输入、选中项、滚动位置等合理状态。
- 当前已经有真实功能的单位换算继续可用。
- 方程 / 不等式 / 函数入口在页面达到基本可操作和正确反馈后开放。
- 化学与物理入口暂不展示成已完成能力。

验收：

- 每个可点击目录项都能进入真实页面，不留下空白占位页。
- 二级页面返回动画连续，系统返回和页面返回行为一致。
- 浅色主题、玻璃材质、安全区和 TalkBack 语义一致。
- 360dp 窄屏下标题、输入区和底部操作可用。

### UI-5：方程求解页面

**目标：** 先把常见方程的输入、求解、结果和限制展示流程做完整，再通过适配层接入现有 C5 能力。

页面结构：

- 方程表达式输入区。
- 未知数选择 / 默认变量提示。
- 可选区间与必要的条件设置。
- 主操作“求解”。
- 结果摘要：唯一解、多解、无解、无穷多解、周期解族。
- 定义域 / 增根剔除 / 原式验证信息。
- 可展开的步骤摘要。
- 不支持题型解释。

工作项：

- 首轮接入已实现的一次、二次、三次、分式、部分绝对值、根式、受限指数 / 对数及已完成的周期三角方程。
- 处理周期解族时支持用户指定区间；没有指定区间时明确显示周期表达形式，而不是擅自截断成少量数值。
- 保留原式的定义域约束、增根检查和 solver typed error。
- 页面不把 C5.1–C5.18 的各 solver 类直接写进 Composable。

验收：

- 每一种已开放类型均有黄金题、边界题和错误题。
- 结果可以复制，恢复输入后可以再次求解。
- Unsupported 有清楚的能力边界。
- 无解 / 无穷多解与求解失败可区分。

### UI-6：不等式页面

**目标：** 以区间 / 解集为中心展示不等式结果。

页面结构：

- 不等式表达式输入。
- 严格 / 非严格符号完整显示。
- 未知数与可选区间。
- 求解按钮。
- 数轴 / 区间表达结果。
- 排除点、定义域空洞与端点开闭状态。
- 结果文本和复制操作。

首轮接入：

- 一至三次多项式不等式。
- 分式不等式。
- 以上能力已经存在的严格 / 非严格端点和分母零点处理。

验收：

- 开闭区间、孤立点、多个区间、空集和全体实数显示正确。
- 分母零点不能因为约分而从原式定义域中消失。
- 数轴图形与结构化区间结果一致。
- 不支持根式 / 指数 / 对数 / 三角不等式时返回 Unsupported，不误报无解。

### UI-7：函数分析与图像页面

**目标：** 先用现有 C7 能力做出可操作的函数工具，再逐步扩展一般函数表达式。

首轮页面能力：

- 选择输入方式：函数 / 点集。
- 点集编辑：添加、修改、删除坐标点；重复 x、非有限值和点数不足有明确反馈。
- 拟合类型：一次、二次、三次、反比例；只显示真实支持的模型。
- 输出拟合表达式、参数和必要的数据摘要。
- 图像区域提供坐标轴、刻度、缩放、平移、重置和探针。
- 数值表和图像使用相同的函数模型 / 采样结果。
- 反比例函数在 x=0 两侧分段，任何断点都不能跨越连线。

后续增强：

- 函数输入框接入通用表达式 parser 与 FunctionEvaluator。
- 增加多函数比较、交点、关键点和参数滑块。
- 逐步支持绝对值、根式、指数、对数、三角、分段和有理函数。
- 逐步增加定义域、值域、单调、奇偶、周期、渐近线等性质分析。

验收：

- Canvas 只负责绘图，不负责求值。
- 缩放 / 平移后采样任务可取消；旧视口结果不覆盖新视口。
- 不跨越极点、空洞和定义域断点连线。
- 探针、数值表、求值结果一致。
- 真机拖动和缩放不明显掉帧或抢走页面滚动手势。

### UI-8：本地历史与恢复

**目标：** 使计算过程可重复使用，不强制账号和联网。

工作项：

- 保存表达式、题型、输入参数、结果摘要、创建时间和可恢复的结构化输入。
- 按计算 / 方程 / 不等式 / 函数 / 单位类型筛选。
- 支持搜索、删除单条和清空。
- 点击记录恢复到对应工具页，而不是把所有数据塞回普通计算输入框。
- 历史为空时提供轻量空状态。
- 本地普通计算历史与未来 AI 云端对话记录保持不同数据模型和访问边界。
- 选择合适的本地持久化方案；若采用 Room，先评估当前工程依赖和 schema migration，不重复保存派生 UI 状态。

验收：

- 进程重启后历史仍在。
- 删除和清空可验证，恢复的数据正确。
- 大量记录滚动流畅。
- 普通计算无需登录。
- 历史记录不含不必要的敏感内容。

### UI-9：通用题目编辑器与增强键盘

**目标：** 在基础计算主页已经可用后，建设能承载复杂题目的结构化编辑器。

编辑能力：

- 普通文本段落和多行题干。
- 数学表达式块、分数、根式、上下标、方程组。
- 矩阵、向量、区间、绝对值和分段函数模板。
- 化学式 / 反应箭头 / 状态符号（为后续化学工具准备）。
- 物理量、单位和科学计数法（为后续物理工具准备）。
- 图片题输入留作独立能力，不阻塞纯文本 / 公式编辑器第一版。

编辑操作：

- 光标、选区、剪切 / 复制 / 粘贴。
- 撤销 / 重做。
- 模板嵌套编辑、退格和光标退出规则。
- 符号搜索；未收录符号仍允许自由文本输入。
- 题目文档 serializer / restore。
- 系统键盘主动切换。
- 输入状态和题目 revision，避免异步结果归属到旧题目。

实现边界：

- 首轮不做 Android 系统级全局 IME；采用 App 内专用键盘。
- 基础计算器不必等待完整 QuestionDocument 才能交付。
- 结构化模板必须使用编辑事务，不能用插入一段不可编辑的富文本字符串代替。

验收：

- 中文 / 英文 / 数学符号 / 多行文本可以混合输入。
- 嵌套模板可继续编辑，不会卡死光标。
- 撤销 / 重做、粘贴、旋转恢复正确。
- 题目结构可以序列化、反序列化且不丢失公式结构。

### UI-10：界面阶段收尾与真机体验

- 软键盘显示 / 隐藏、安全区和系统返回。

- 连续点击、长按退格、滑动编辑、拖动图表、滚动列表的手势仲裁。
- TalkBack 标签、焦点顺序、状态播报和触控目标。
- 本地离线计算、空状态、错误状态和恢复状态。

## 6. 第二阶段：数学能力系统性补齐

数学补齐从 UI-10 通过后开始；但如果 UI 接入过程中发现一个极小的算法缺口，允许修复阻断问题，不允许借机扩成新的大型题型批次。

### M-0：统一题型识别与 SolverCapability 注册

目标：让新增题型只需声明输入结构和能力，不需要重写页面。

工作项：

- 建立 ProblemType / SolverCapability / SolverDescriptor。
- 将当前 C5、C6 solver 包装为 adapter。
- 统一输入模型、变量名、区间和限制条件。
- 统一 Success、NoSolution、InfiniteSolutions、Unsupported、InvalidInput、DomainError、NumericFailure。
- 题型检测不确定时允许用户手动选择类型，不把启发式分类当作数学证明。
- 建立能力目录，页面按注册能力展示支持范围。

验收：

- 当前所有已有 solver 可从同一应用服务调用。
- 每个 solver 的能力限制可被 UI 查询。
- 未注册题型明确 Unsupported。
- 原有 C5 / C6 的结果语义和回归测试不回退。

### M-1：通用函数表达式与函数分析

优先级：高。它能直接复用 UI-7 图像和探针交互，也能为方程、不等式和后续导数提供共同底座。

范围：

- 将当前表达式 AST 扩展为变量表达式求值，不只支持常数表达式。
- 先支持多项式与有理函数表达式。
- 再支持绝对值、根式、指数 / 对数和三角函数。
- 统一函数定义域与原式限制，防止约分丢失定义域空洞。
- 通用求值器提供有限值 / 非有限值 / 精度失败的 typed result。
- 图像自适应采样、极点 / 断点检测和视口缓存复用现有 Graph UI。

验收：

- 表达式求值与已存在 solver 的回代值一致。
- 定义域和可去间断点保留。
- 数值采样不会跨断点连线。
- 单元测试覆盖有限值、极端值、溢出、下溢、精度损失与不连续点。

### M-2：方程覆盖扩展

优先级：高。以高中常见题型为目标，不按单个表达式变体无限拆号。

分批范围：

1. 一元多项式：加强四次及以上的可解情形；明确一般高次不可解析或数值法不适用的范围。
2. 分式、根式与绝对值：扩大内部表达式次数、嵌套和多重分支；保留定义域与增根检查。
3. 指数 / 对数：扩大底数、复合函数和同底变换后的可靠范围。
4. 三角：补充常见恒等变换、同角 / 不同角等式、含参数和区间解。
5. 方程组：逐步从二元一次扩展到可验证的非线性 / 多元子集。
6. 参数方程：先选择可判定的常见模型，明确分支条件与参数范围。

验收：

- 每个题型有明确支持边界，不接受“尽量给一个数值”。
- 候选解回代原式；定义域、增根、重根和周期分支处理正确。
- 无解、无穷多解和求解器能力不足严格区分。
- 测试包含常规样例、边界、退化、数值极端和错误输入。

### M-3：不等式覆盖扩展

优先级：高。以解集正确性为核心，先建立可验证区间，再做复杂变换。

范围：

- 根式不等式：定义域和平方后的等价条件。
- 指数 / 对数不等式：底数大于 / 小于 1 的单调方向、真数定义域。
- 三角不等式：周期区间、端点、指定范围和多个周期截取。
- 含绝对值 / 分式复合式：分段、零点、极点和符号区间。
- 含参数不等式：先做有限且有明确分支边界的子集。
- 必要时采用数值区间分析，但必须标明数值近似，不可伪装成精确解析解。

验收：

- 严格 / 非严格端点和定义域排除点正确。
- 图示数轴与结构化区间结果严格一致。
- 不因表达式化简丢失原式限制。
- 数值近似与解析结论清晰区分。

### M-4：高中数学其他主线

在 M-1 到 M-3 基础稳定后，按模块实施，每个模块先建立领域模型与样例集，再决定复用现有实现还是引入成熟开源库。

| 模块 | 主要内容 | 首批实现目标 | 高阶内容与限制 |
|---|---|---|---|
| 数列 | 等差、等比、通项、前 n 项和、递推 | 常见封闭形式、基本求和 | 复杂递推、数列不等式和综合证明 |
| 平面向量 | 坐标、模、点积、夹角、共线 / 垂直 | 二维与三维基础运算 | 向量综合证明与参数最值 |
| 解析几何 | 直线、圆、抛物线、椭圆、双曲线 | 标准方程、距离、交点、位置关系 | 弦切线、轨迹和复杂参数问题 |
| 平面几何 | 三角形、圆、相似、全等、面积 | 可解析坐标 / 度量计算 | 复杂证明、辅助线和几何推理 |
| 立体几何 | 点线面、空间向量、角与距离 | 坐标化和基础空间运算 | 多条件证明与复杂空间关系 |
| 概率统计 | 计数、排列组合、古典概率、条件概率、独立性、统计量 | 确定性计数和概率计算 | 随机变量分布和综合建模 |
| 导数与变化率 | 常见函数求导、切线、单调、极值、最值 | 多项式与常见初等函数 | 参数恒成立、复杂综合证明 |
| 综合应用题 | 函数建模、单位、最值、方案决策 | 常见文字转模型和计算 | 多步骤建模与论证 |

不把全部高中数学塞进一个 solver。各模块允许独立发布，但必须通过公共输入、结果、错误和历史接口。

### M-5：开源库评估和复用

用户已明确希望在合适时复用开源项目，不要求所有算法自研。

每个模块开始前先完成简短技术评估：

- 是否存在成熟的 JVM / Kotlin 兼容库。
- Android API / minSdk / 包体积 / 性能是否适配。
- 许可证是否允许当前项目分发；记录许可证和依赖版本。
- 输入输出语义是否能映射到本项目 typed result。
- 是否保留原式定义域、数值稳定性和可验证性。
- 是否有维护状态、测试、已知缺陷和安全风险。

选择规则：

- 成熟库能满足准确性和许可要求时优先封装复用。
- 小型且关键的代数逻辑可继续纯 Kotlin 实现。
- 不能仅因库有漂亮 API 就直接接入；必须有本项目 golden tests。
- 不复制整套大型 CAS 到 UI 主线程，也不将不透明二进制结果直接展示给用户。
- 若自研，仅实现明确的一小片能力，不重新实现已有库覆盖的全部功能。

### M-6：化学与物理（独立学科线）

化学和物理不是本轮普通计算主页的阻断项，安排在数学主线与题目编辑器稳定后。

化学：

- 化学式 / 方程结构化输入。
- 原子守恒、电荷守恒和配平。
- 离子方程式、氧化还原与电子转移。
- 条件反应产物候选和物质状态。
- 有多种可能产物时列出条件分支，不编造唯一反应。

物理：

- 物理量、单位、量纲、有效数字。
- 运动学、力学、动量、功与能、电磁学等常见模块。
- 已知量 / 未知量结构化，公式适用条件和单位检查。
- 多过程文字建模可在后续接入 AI 辅助，但本地计算逻辑与 AI 文本分开。

## 7. 全阶段测试与质量门槛

### 7.1 每个页面 / 数学模块均需覆盖

| 测试层 | 最低要求 |
|---|---|
| Model / domain 单测 | 常规、边界、退化、错误输入、数值极端 |
| Adapter 测试 | 路由到正确能力，typed result 映射不丢信息 |
| ViewModel 测试 | 输入事件、状态转换、取消和过期任务 |
| Compose UI 测试 | 关键控件可见、可操作、状态正确 |
| 无障碍 | 内容描述、焦点顺序、点击目标、错误播报 |
| 性能 | 高频输入、键盘动画、图像拖动、列表滚动 |
| 回归 | 旧样例、旧版兼容和已通过阶段不得倒退 |

### 7.2 数学结果测试维度

- 输入语法、优先级、隐式乘法、一元正负和括号。
- 空输入、未完成输入、非法输入。
- 定义域、原始分母零点、可去间断点、增根。
- 重根、多个解、周期解族、开闭区间端点。
- 大系数、小系数、溢出、下溢、非有限中间值和精度损失。
- 原式回代、交叉验证以及近似结果的残差。
- Unsupported 不可等同于 NoSolution。

### 7.3 CI 与真机验收必须分开写

- JVM 单元测试通过只证明执行到的纯 Kotlin 测试通过。
- Android test 源码编译成功不代表 instrumentation test 已执行。
- APK 组装成功不代表交互和动画在真机正常。
- 页面动效、键盘手势、玻璃材质、图像缩放和刷新率体验必须在目标设备验证。
- 用户暂缓的真机验收继续标为暂缓，不得自动写成通过。

不使用一个无法核实的“数学完成百分比”。以能实际使用的产品里程碑衡量。

## 10. 具体执行规矩

1. 一次只做一个可独立验收的小步骤，不把多个大页面塞进一个 PR。
2. 每一步先检查 main 最新提交和状态账本，再建立分支。
3. 先明确本步要修改的页面、接口和测试，再动代码。
4. 不为了 UI 临时复制数学逻辑；不为了算法改动已验收的玻璃主壳。
5. 只开放真实可用的按钮；不做大量空壳入口。
6. 每个功能都要覆盖加载、空白、输入、成功、错误和不支持状态。
7. 完成后运行与改动对应的 JVM / Compose / 资源检查和 Debug 构建。
8. PR 合并后更新 README、IMPLEMENTATION_STATUS 和对应专项计划。
9. CI、APK、模拟器和真机状态分开记录。
10. 只有达到本里程碑验收标准，才把阶段标为完成。
