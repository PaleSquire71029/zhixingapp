# 知行计算器原生页面设计构想

> 版本：0.2（导航与图标修订稿）  
> 日期：2026-11-06  
> 目标设备基线：iQOO Neo5 活力版，竖屏优先  
> 技术边界：Kotlin + Jetpack Compose；复用现有 Zhixing Theme、Backdrop 与液态玻璃组件

## 1. 设计目标

这不是把旧网页缩小后放进手机，而是重新设计一个以单手输入为中心的原生计算器。

核心原则：

1. **键盘优先。** 打开“计算”页就能立即输入，不先看大幅 Hero、介绍卡片或网页式工具目录。
2. **结果优先。** 算式清晰可编辑，结果有足够字号；复杂过程默认收起，需要时再展开。
3. **功能分层。** 普通 / 科学计算留在计算页；方程、不等式、函数分析、单位换算、化学配平各有独立工具页，不挤在一张超长页面里。
4. **原生交互。** 使用 Compose 状态、触摸反馈、无障碍语义和系统安全区；不使用 WebView、网页 DOM 或网页式卡片栅格。
5. **玻璃有重点。** 复用真实 Backdrop 采样和现有材质设置，但不把每个按键都做成高成本模糊玻璃。输入与结果区、模式切换和导航是材质重点；数字键必须首先清晰、稳定、好按。

## 2. 计算页整体结构

竖屏按从上到下的操作顺序组织：

- **顶部轻工具栏：** 页面标题“计算”；右侧提供“标准 / 科学”模式入口和必要的编辑辅助。高度克制，不另放大品牌 Hero。
- **算式显示区：** 当前表达式在上方，支持多行、光标定位、局部编辑；右侧或下一行提供退格操作。内容较长时在表达式区域内部滚动，不推动整个键盘跳动。
- **结果区：** 最新结果使用明显的大字号，表达式与结果层级分明。输入过程中可显示预览值；按下等号后结果稳定落位。错误提示紧贴算式区域，说明原因，不弹出遮挡键盘的网页式 toast 卡片。
- **科学函数条：** 标准模式收起；科学模式展开为可横向浏览的辅助函数区，提供 sin、cos、tan、ln、log、√、幂、π、e 等，不改变主数字键盘的位置。
- **主键盘：** 固定在屏幕下半部，四列、五行，按拇指操作设计；键帽尺寸和间距一致，等号为唯一明确的主操作强调色。
- **全局底部导航：** 调整为「计算 / 知行 AI / 工具 / 我的」；保留现有液态胶囊位移动效，但重新设计四个图标；键盘与导航之间留有安全间距，不能互相覆盖。

建议的标准键盘逻辑：

| 行 | 按键 |
|---|---|
| 1 | AC、括号、百分号、除号 |
| 2 | 7、8、9、乘号 |
| 3 | 4、5、6、减号 |
| 4 | 1、2、3、加号 |
| 5 | 正负号、0、小数点、等号 |

退格放在算式编辑区的固定小操作位，避免为了容纳所有功能把每个按键缩小。括号键采用一次输入成对括号、光标留在括号内部的方式；长按或辅助操作可切换单侧括号。

## 3. 视觉方向

### 3.1 不采用网页结构

明确避免以下做法：

- 不把首页 Hero 卡片缩小后当作计算器内容区；
- 不将每个功能做成一排排大卡片；
- 不使用网页式顶部大标题 + 多段介绍 + 长页面滚动；
- 不在数字键盘上方堆叠工具卡、广告位或 AI 对话预览；
- 不把旧网页的按钮颜色、网格比例和信息顺序直接照搬。

计算页应该像一个专用设备界面：打开即进入输入状态，视线自然从算式落到结果，再落到键盘。

### 3.2 材质与层级

- **背景：** 延续现有知行浅色渐变，不另换深色主题。
- **算式 / 结果：** 使用轻透的 Backdrop 表面，边缘高光细腻，文本区域关闭折射和色散，保证数学符号不变形。
- **数字键：** 使用高辨识度的浅色实体感键帽，带轻微环境反射、柔和内外层次和按压形变；不要每个键都叠加独立重模糊。
- **运算符键：** 通过低饱和色阶与字重区分，不使用一整列刺眼纯色块。
- **等号键：** 唯一主强调键，按压时产生短促下沉、柔和高光和轻微回弹。
- **导航与模式控件：** 沿用已验证的液态胶囊、真实背景采样和弹簧移动逻辑。
- **圆角：** 键帽比大面板更紧凑；同一层级统一半径，不让每个元素拥有不同的夸张圆角。

## 4. 操作与动效

- 默认使用应用内数字键盘，不自动弹出系统输入法；表达式区仍应支持光标移动和局部修改。
- 按键按下立即反馈，松手短弹簧恢复；连点时每次输入都要保留，不因动画协程取消而漏字或重复。
- 按键触控区域至少满足舒适点击尺寸；视觉键帽可以略小于实际触控区域。
- 可提供轻量触觉反馈设置，不能让震动或动画拖慢连续输入。
- 结果更新、表达式排版和按键动画分离；求解、函数采样、历史写入不得占用主线程帧路径。
- 以当前已在目标手机生效的 120 帧体验为基线，避免新增无意义的持续动画、全键盘独立模糊和每帧全页重组。
- 屏幕高度不足时优先压缩顶部空白和辅助函数条，不压缩数字键的可点区域。

## 5. 科学计算与工具页面的边界

- **标准 / 科学：** 同一个计算工作区切换；科学键只增加辅助函数，不把基础数字键重新排列。
- **方程 / 不等式：** 独立求解页，输入区、变量 / 条件设置、结果区和可展开推导分层，不和普通计算键盘混在一起。
- **函数：** 独立函数分析页，先输入函数或点集，再显示关键性质与图像；图像可单独放大查看。
- **单位换算：** 独立双向换算页，输入值、源单位、目标单位分开，空输入保持为空而不是自动变成 0。
- **化学配平：** 独立化学工作区，元素搜索和化学专用键盘按需出现；气体 / 沉淀标记只出现在结果表达式，不堆到键盘上。
- **知行 AI：** 继续使用全局“知行AI”入口；计算页不放常驻聊天框，不让 AI 抢占键盘和结果空间。
- **我的：** 作为第四个全局入口，集中提供个人资料 / 本地使用状态、历史记录、材质与应用设置；历史与设置不再单独占用底部导航位置。

## 6. 页面状态

至少设计并测试以下状态：

1. 初始空白：输入提示轻量显示，键盘立即可用。
2. 正在输入：表达式可编辑，结果预览不跳动。
3. 已得结果：结果视觉突出，表达式仍可点选修改。
4. 多行 / 长表达式：编辑区内部滚动，键盘位置稳定。
5. 计算错误：错误原因就近显示，键盘保持可用。
6. 科学模式：辅助函数条展开，主数字键位置不变。
7. 键盘连续输入：快速点击、长按退格和连续运算符均不丢输入。

## 7. 建议实施顺序

此设计稿只作为后续 UI 阶段的产品与交互基线，本轮不实现 UI。实际开发仍按计算核心迁移计划执行：

1. C0.1 先建立旧算法黄金样例；
2. C1–C3 完成 Tokenizer、AST / Parser 与常数表达式求值；
3. 后续逐步实现代数、方程、不等式、函数、单位与化学能力；
4. 到 C12 再实现本设计中的最小原生计算页，并且只开放已完成的计算能力；
5. UI 接入后，再逐项验收按键、长表达式、横竖屏、无障碍与 120 帧下的连续输入体验。

## 8. 当前不做的内容

- 不在本设计稿阶段修改 MainActivity 或新增空壳页面；
- 不先做装饰性图表、动态背景或复杂过场；
- 不照搬旧网页布局；
- 不因 UI 设计提前实现未完成的方程、函数、化学等入口；
- 不强制登录，不把普通本地计算绑定到云端服务。


## 9. 底部导航与「我的」页面重构

### 9.1 一级导航结构

最终底部导航固定为四项，顺序如下：

1. **计算**：默认首页，进入标准 / 科学计算工作区。
2. **知行 AI**：进入独立 AI 对话工作区。
3. **工具**：进入工具目录，再进入方程、不等式、函数、单位换算、化学等独立功能。
4. **我的**：集中管理历史、材质设置和应用相关设置。

不再保留独立的「历史」一级 Tab。原先占据第四个位置的历史入口由「我的」替换；「历史」变为「我的」页面中的核心入口。材质设置也从首页顶部按钮迁入「我的」，首页不再常驻放一个设置入口。

### 9.2 「我的」页面布局

采用原生设置中心的分组结构，而不是个人中心网页常见的大头像横幅和多张运营卡片：

- **顶部身份区：** 左侧为简洁的知行抽象头像 / 品牌符号，显示「我的」标题和轻量状态。普通本地计算不强制登录，不制造虚假的账号资料或会员等级。
- **最近使用：** 小面积显示最近一条计算记录与「查看全部」入口；如果没有历史，显示简洁空状态，不放大幅插画。
- **计算记录分组：** 进入独立历史页，支持按计算类型筛选、搜索、删除、批量清理；点击一条记录恢复原始表达式 / 工具输入。云端 AI 对话记录仍遵循各产品自身的同步规则，不与本地计算历史混成同一个数据源。
- **材质与外观分组：** 进入现有材质设置页，保留性能模式、透明程度、背景模糊、折射强度、高光、环境反射、触摸反馈等能力。
- **应用设置分组：** 后续承载触觉反馈、按键声音、默认角度 / 计算模式、数字格式、隐私与数据管理、关于与版本信息。未实现的设置不得先显示成可点击的空入口。
- **底部信息：** 应用版本、构建版本和必要的帮助 / 反馈入口，弱化显示，不抢占主要内容。

「我的」本身不应要求登录。只有未来明确需要云同步或账号功能时，才展示对应的真实登录状态；未登录时本地历史、材质设置和普通计算继续可用。

### 9.3 四个导航图标的统一设计语言

图标使用**自绘 Compose ImageVector / Path**，不直接拼一套系统默认图标。四个一级图标共享同一套几何规范：

- 统一 24 × 24 dp 画布，视觉内容居中，四周留出一致安全边距；
- 默认描边约 1.8–2 dp，圆角端点 / 圆角连接；避免尖锐、机械的线段；
- 图形以轮廓为主，选中态仅在局部填充一层知行浅蓝或柔和蓝紫，不整枚图标实心填色；
- 未选中态使用低饱和蓝灰，选中态提高明度和对比度；颜色与文字选中状态一致；
- 动效只做轻微缩放、线条补全 / 局部填充和胶囊滑动联动，不旋转、不弹跳过度；
- 图标与标签对齐，图标视觉重量一致，不允许某一枚明显比其他图标大或复杂。

图标概念：

| 导航 | 图形概念 | 视觉识别点 |
|---|---|---|
| 计算 | 一块圆角显示窗，下方三枚有节奏的数字按键点阵，并在右下角留一个运算标记 | 不是传统计算器 Emoji；用「显示 + 键位」抽象表达计算 |
| 知行 AI | 两条相互呼应的圆弧 / 对话轨迹，中间以一个连接节点形成连续信息流 | 不使用机器人头、星星、芯片或普通聊天气泡；与品牌抽象符号呼应 |
| 工具 | 四个不同大小的圆角几何模块围绕中心错位排布，形成一个有秩序的工具矩阵 | 不画扳手、螺丝刀等具象工具；表达多工具组合 |
| 我的 | 圆形头像核心与下方柔和肩部弧线，外围用不闭合的圆角轮廓承托 | 轮廓简洁，避免默认素材头像的细碎五官 |

### 9.4 「我的」页面内部图标

「我的」内部的历史和设置属于二级功能，图标与一级导航同一线宽和圆角：

- **历史记录：** 圆角回环 / 时钟轨迹，指针落在右上象限；避免过多刻度，缩小后仍清楚。
- **材质设置：** 三条不同长度的柔和滑杆，旋钮错位排列；让用户联想到已完成的玻璃材质调节，而不是通用齿轮。
- **应用设置：** 一个轻量圆角控制面板，内部只有两到三条短线与一个状态点；与材质设置区分。
- **隐私与数据：** 简化盾形外框与中心小圆点，不使用复杂锁头堆叠。

历史入口和设置入口使用简洁行项目，不做成两张巨大的彩色功能卡片。点击区域完整覆盖整行，图标仅作识别，不成为唯一触控目标。

### 9.5 图标实现与验收

- 每个图标拆成独立 Vector / ImageVector，统一命名并由导航目的地引用；不在 MainActivity 内写大量临时 Canvas 绘图。
- 选中 / 未选中共享同一轮廓和几何尺寸，仅改变局部填充与颜色，避免切换时图标位移。
- 使用 TalkBack 描述「计算」「知行 AI」「工具」「我的」，不把装饰路径重复读出。
- 在 360dp 左右窄屏、目标设备密度与系统字体放大场景下检查图标与文字间距、触控范围和视觉重心。
- 四枚一级图标先作为一套整体验收，再进入 Compose 代码；不可混用 emoji、系统默认填充图标和自绘线性图标。

## 10. 导航调整实施约束

- 本次仍是设计决策，不改变当前 App 代码和占位路由。
- 真正实现导航时，应同步调整目的地模型、导航标签、图标引用、返回栈和状态恢复，而不是只改显示文字。
- 将历史与设置放进「我的」后，确保材质设置返回后仍回到「我的」原位置；历史详情返回后恢复筛选 / 滚动状态。
- 先做「我的」导航壳和真实可用的历史 / 材质设置入口，再逐步迁移历史数据与更多设置；没有功能的设置项不显示。
