# 知行计算器：高中题型、专用输入、函数图像与 AI 协同规划

> 规划版本：1.0  
> 制定日期：2026-11-08  
> 目标仓库：`PaleSquire71029/zhixingapp`  
> 状态：**产品与技术规划已确定；本文件本轮只写规划，没有开始实现输入法、题型求解器、函数图像或 AI 客户端。**

## 0. 本次需求的最终方向

计算器不能只是一台四则运算器，也不能变成一个每道题都调用大模型的聊天应用。目标是把它做成一套面向高中学习的本地计算与复杂题求解工具：

1. **简单运算完全本地执行。** 普通四则、百分数、幂、根式、常规表达式、已覆盖的简单方程与单位换算，不调用 AI，不上传输入内容。
2. **复杂题才出现 AI 能力。** 本地能力目录判断题型复杂、条件较多或超出当前求解器范围时，显示 AI 分析 / AI 解题入口；用户主动选择后才发送题目。
3. **AI 负责复杂推理与解题过程。** 输出不仅是答案，还要包含识题、条件整理、思路、分步推导、结论、检验与易错点；不允许 AI 伪装成本地精确计算器。
4. **输入不受固定按键限制。** 建立应用内专用数学 / 理化输入键盘，并提供普通文字、公式、结构化模板、符号搜索、粘贴和原始文本兜底。键盘未提供的内容仍能通过自由文本或可编辑公式输入。
5. **函数图像以准确、易用为第一优先级。** 图像由本地数学表达式与数值采样引擎绘制，不让 AI 生成图像，也不以稀疏点简单连线冒充连续函数。
6. **原生优先、模块分层。** Kotlin / Compose 实现，不把旧网页整体塞进 WebView；算法、编辑器、键盘、图像和 AI 各有清晰边界。

## 1. 产品边界与优先级

### 1.1 本地、AI 与图像的职责

| 能力 | 默认执行方式 | 什么时候用 AI |
|---|---|---|
| 简单算式与科学计算 | 本地求值 | 默认不显示 AI 入口、不发请求 |
| 简单代数化简 / 已覆盖的方程 | 本地符号算法 | 题目多条件、含参数或超出本地能力时 |
| 常规函数绘图 | 本地表达式求值与采样 | 只在用户要求解释性质、复杂证明或模型未覆盖时 |
| 复杂高中数学题 | 先识别题型与提取本地可用信息 | 显示 AI 分析 / AI 解题入口，由用户主动选择 |
| 化学配平 | 本地精确整数算法 | 产物预测、反应条件不唯一、复杂离子反应等 |
| 物理计算 | 公式、单位和量纲的本地确定性计算 | 多过程综合题、文字题建模或超出本地覆盖范围时 |
| 题目讲解 / 多步证明 | 本地能严格完成的部分优先 | 需要语言推理、证明组织或跨章节分析时 |

本地计算器始终优先承担确定性工作。AI 是复杂问题的补充推理器，不代替本地运算、图像引擎或化学守恒算法。

### 1.2 复杂度判断：不靠 AI 再判断要不要 AI

建立本地 `SolverCapabilityRegistry`（求解能力目录）和 `ProblemComplexityAssessment`（题目复杂度评估）：

- 已支持且低复杂度：直接本地完成，AI 入口隐藏或收在明确的扩展菜单中。
- 已支持但复杂度较高：展示本地结果，并提供「AI 分析过程」或「独立核验」。
- 部分支持：列出本地能完成的步骤，再提供「AI 补全复杂部分」。
- 暂不支持：保留输入内容，提供「让 AI 尝试解题」；不得伪报本地失败为“无解”。
- 题目本身信息不足：先提示缺失条件；AI 可以帮助指出歧义，但不能擅自补充条件。

初始复杂度信号采用确定性规则，而非额外调用模型：

- 多个未知数、参数分类讨论、分段条件、复合函数或多层分式；
- 多个题目条件之间需要联合建模；
- 含证明、推导、最值、范围、存在性或应用题文字建模；
- 需要跨函数、数列、几何、向量、概率等多个知识模块；
- 本地 solver 明确返回 `Unsupported` / `NeedsReasoning`，而不是数值错误或程序异常。

复杂度规则必须可测试、可解释、可由题型能力注册表更新。不要单纯用题目长度或符号个数认定复杂题，也不能因为 AI 网络不可用就阻断本地结果。

### 1.3 AI 触发规则

- 不在按键输入、按下等号、页面打开或图像拖动时自动调用 AI。
- 简单计算界面不放显眼的 AI 按钮，避免用户误以为每题都必须联网。
- 达到复杂条件或本地能力不足时，在结果区域出现按题型定制的 AI 入口。
- AI 请求前展示本次将发送的题目、公式和必要上下文摘要；用户可删改或取消。
- 用户明确点「AI 分析」/「AI 解题」后才发请求。除非用户主动开启“对当前复杂题自动分析”偏好，第一版不提供后台自动发送；该偏好未来即使开放也必须逐题确认数据发送范围。
- AI 不得覆盖本地精确答案；差异时并列呈现，并标记“AI 推导与本地结果不一致，需要复核”。

## 2. 高中题型支持范围

采用“题型目录 + 求解能力注册表 + 本地 / AI 双路径”，而不是一个超长的统一解题页面。首发以高中数学为主，化学和物理分批扩展。

### 2.1 高中数学：第一优先级

| 模块 | 需要支持的内容 | 首要本地能力 | 复杂题 AI 用途 |
|---|---|---|---|
| 数与式 | 实数、分数、根式、绝对值、指数、对数、整式、分式、因式分解 | 精确解析、化简、求值、定义域 | 多步恒等变形、复杂化简解释 |
| 方程 | 一元一次 / 二次 / 三次基础、分式、根式、指数、对数、三角方程、方程组 | 低次解析解、定义域和增根检查 | 高次、含参、超越方程和复杂方程组 |
| 不等式 | 一元一次 / 二次、分式、高次基础、绝对值、含参不等式 | 临界点、符号区间、定义域、端点开闭 | 多参数分类、复合不等式、复杂恒成立问题 |
| 函数 | 定义域、值域、奇偶性、单调性、周期、零点、极值、对称性、复合与反函数 | 可证明的基础性质、数值检查与图像 | 多性质综合、抽象构造、参数问题 |
| 指数与对数 | 图像、性质、运算、方程与不等式 | 本地函数计算和图像 | 复杂换元、参数分类、综合压轴题 |
| 三角函数 | 诱导公式、恒等变换、图像、周期、最值、三角方程 | 弧度计算、基础恒等式、图像 | 多角度恒等证明、参数与区间综合 |
| 数列 | 等差 / 等比、通项、求和、递推关系 | 常见类型与有限项计算 | 复杂递推、数列不等式、归纳证明 |
| 平面向量 | 坐标、数量积、模、夹角、平行垂直、几何关系 | 向量代数与坐标运算 | 向量与几何综合、参数关系 |
| 解析几何 | 直线、圆、椭圆、双曲线、抛物线、轨迹与位置关系 | 标准方程、交点、距离和基础判别式 | 多条件轨迹、弦 / 切线综合、参数最值 |
| 立体几何 | 点线面关系、角与距离、空间向量 | 坐标 / 向量模型和基础数值 | 证明题、复杂空间关系与辅助线思路 |
| 平面几何 | 三角形、圆、相似、全等、面积、几何证明 | 可解析的坐标与度量计算 | 证明策略、辅助线、复杂图形推理 |
| 概率统计 | 排列组合、古典概型、条件概率、独立性、随机变量、统计量 | 确定性计数与概率运算 | 复杂情境建模、分布综合解释 |
| 导数与变化率 | 导数、切线、单调区间、极值、最值 | 符号求导和已覆盖多项式 / 常见函数性质 | 参数最值、含参恒成立、综合证明 |
| 综合应用题 | 函数建模、实际情境、最值、方案选择 | 单位、变量和基础模型 | 文字转数学模型、多步骤推理与方案论证 |

课程范围和地区差异通过题型配置层控制；不把某个地区教材版本的内容硬编码成所有用户的唯一标准。

### 2.2 化学

- 化学式与结构化学方程式输入。
- 配平、离子方程式、电荷守恒、氧化还原、电子转移。
- 反应物类别、条件、物质状态、现象和产物候选。
- 物质的量、浓度、气体、溶液、化学计量关系。
- 有条件的反应必须列候选并说明所需条件，不允许 AI 编造唯一产物。
- 原子守恒和电荷守恒优先由本地算法核验；AI 用于复杂反应推断、解释和多条件分析。

### 2.3 物理（数学主线之后接入）

- 物理量、单位、量纲、科学计数法和有效数字。
- 运动学、牛顿定律、动量、功与能、圆周运动、万有引力。
- 电路、电场、磁场、电磁感应。
- 热学、波动、光学和近代物理基础。
- 先将已知量、未知量、单位和适用定律结构化；本地负责公式数值计算和单位检查。
- 多过程综合、受力分析、图像题与文字建模提供 AI 解题与讲解。

## 3. 通用题目输入系统：专用输入法

### 3.1 产品形态决定

第一版采用**计算器 App 内嵌的专用输入面板**，而不是先开发一个必须到 Android 系统设置里启用的全局第三方输入法（InputMethodService）。

理由：

- 用户进入计算器即可使用，不必切换系统默认键盘；
- 可以根据数学 / 化学 / 物理题型动态切换键盘布局；
- 能同时操作光标、公式模板、上下标、矩阵和多行题目；
- 无需获得系统级键盘权限，也避免把其他应用中输入的隐私数据带入项目；
- 系统键盘仍可由用户主动切换，用于大段中文描述、作文式题干或特殊文字。

在产品体验上它就是计算器专用输入法；若未来确实需要在其他应用中输入数学公式，再独立评估系统级输入法，不能让它成为当前计算器可用性的前置条件。

### 3.2 “任何题都能输入”的底线

不能把输入能力限制成一组固定数学按键。每个题目编辑器至少有以下四种互补输入方式：

1. **普通文字模式：** 可输入完整中文题干、英文、数字、标点、条件描述和换行。
2. **数学公式模式：** 用分数、根式、上下标、积分、求和、矩阵、分段函数等结构化模板输入。
3. **符号搜索模式：** 搜索符号名称、输入 LaTeX 命令或关键字，插入任意 Unicode 数学 / 科学符号。
4. **原始公式 / 文本兜底：** 可直接编辑 LaTeX / 纯文本表达式；暂不支持解析的片段仍保留原文，不得丢弃、自动替换或阻止提交给 AI。

“任何题都能输入”指用户不应被键盘符号目录卡住，所有题干都能通过自由文字、公式文本、符号搜索或粘贴完整表达；它不代表每一种符号都已由本地 solver 求解。

### 3.3 编辑器的数据结构

不把所有内容只存成一个无法区分的长字符串。建立可序列化的 `QuestionDocument`，按顺序保存内容块：

- `ParagraphBlock`：中文 / 英文题干和普通文字。
- `MathExpressionBlock`：结构化数学表达式与原始文本。
- `EquationSystemBlock`：方程组、联立条件。
- `PiecewiseBlock`：分段函数与区间条件。
- `MatrixBlock` / `TableBlock`：矩阵、表格和统计数据。
- `CoordinateBlock`：点、向量、坐标及几何关系。
- `ChemicalFormulaBlock` / `ReactionBlock`：化学式、反应箭头、条件和状态符号。
- `PhysicalQuantityBlock`：数值、物理量、单位和有效数字。
- `ImageReferenceBlock`：后续图片题输入的引用；需用户明确选择 / 发送，不自动上传整张屏幕。

每个块保留原始输入、可解析结构和光标 / 选择位置。若结构化解析失败，原始文本仍完整保留。文档应支持撤销 / 重做、剪切 / 复制 / 粘贴、选区替换和草稿恢复。

### 3.4 专用输入面板布局

顶部为输入模式 / 学科工具条；中部为当前题目编辑区域；底部为可切换的键盘页。键盘应随题型变化，但不能改变用户已经输入的内容或光标位置。

建议键盘页：

| 键盘页 | 主要内容 |
|---|---|
| 基础 | 数字、加减乘除、括号、等号、小数、正负号、退格、回车 |
| 代数 | x/y/t、参数、上下标、幂、根式、绝对值、分数、因式与括号模板 |
| 关系 | 小于 / 大于 / 等于 / 约等于 / 不等于 / 属于 / 包含 / 推出 / 等价 |
| 函数 | f(x)、复合、反函数、分段、定义域区间、sin/cos/tan、ln/log |
| 微积分 | 极限、导数、积分、求和、求乘积、无穷、微分符号 |
| 几何与向量 | 点、线段、角、平行、垂直、向量、模、点积、距离、圆弧 |
| 矩阵与统计 | 行列式、矩阵、括号矩阵、排列组合、概率、均值、方差 |
| 物理 | 希腊字母、矢量、上下标、单位、度数、科学计数法、常见量符号 |
| 化学 | 元素 / 化学式、下标、价态、反应箭头、可逆箭头、条件、电子、电荷、气体 / 沉淀状态 |
| 符号搜索 | 按名称、关键字或 LaTeX 命令查找全部可用符号 |

键盘还需支持：

- 常见模板一键成形：分数、根式、括号、上下标、方程组、分段函数、矩阵、积分、求和。
- 长按显示同组符号变体；最近使用和收藏符号。
- 搜索无结果时允许保留搜索文本，或切换到原始 LaTeX 编辑，不吞掉用户输入。
- 连续输入、快速退格、左右移动光标、上下移动公式位置、选区、撤销 / 重做。
- 大段中文题干时可切换系统键盘；返回专用面板后恢复原光标。
- 窄屏下键盘页横向 / 分组切换，不把触控区域压得过小。

### 3.5 输入语法与兼容

- 建立单一的规范化输入表示，避免界面显示公式与 parser 实际收到的字符串不一致。
- 显示层、文档层、解析层分开：显示可排版，编辑保留结构，解析统一成 Token / AST。
- 每个模板都必须有 round-trip 测试：插入 → 编辑 → 序列化 → 解析 → 再显示，内容不丢失。
- 保留原始字符偏移，以便报错时定位到用户输入位置。
- 新符号如果本地暂不解析，也要保留原始形式并能发送给 AI（需用户确认），不可擅自“修复”为另一个符号。

## 4. 函数图像：准确性与操作体验

### 4.1 基本原则

- 图像由本地解析树 / 函数求值器生成，不调用 AI 绘制曲线。
- 图像和符号求解共享 AST、函数定义域和参数模型，避免“计算器说一个值、图像画另一个值”。
- 不用固定数量的稀疏采样点直接连线作为最终实现。
- 数值采样只能作为图像展示；零点、极值、交点和渐近线若没有经过独立求解和验证，必须标记为数值估计，不能冒充解析证明。

### 4.2 首批函数类型

1. 一次、二次、三次多项式。
2. 反比例与一般有理函数（严格遵循定义域限制）。
3. 幂函数、根式函数、绝对值函数。
4. 指数、对数函数。
5. 常见三角函数及其变换（角度 / 弧度模式明确）。
6. 分段函数、带定义域限制的函数。
7. 多函数同屏比较、参数函数与变换。
8. 用户输入点集后拟合或验证函数，拟合模型与原始点必须同时保留。

后续扩展：参数曲线、隐式曲线、极坐标、函数不等式区域和更复杂的高中解析几何对象。不得为追求“一开始支持全部”而牺牲首批图像的准确性。

### 4.3 绘图引擎

分离为三个纯逻辑层和一个显示层：

- `FunctionEvaluator`：给定 x、参数与表达式，返回有限值、定义域外、奇异点或数值失败。
- `AdaptiveSampler`：按当前屏幕像素误差细分采样；在斜率突变、曲率较大、函数值变化过快或采样点状态变化时加密。
- `DiscontinuityDetector`：利用函数求值状态、定义域限制、相邻点跳变和可用的符号信息识别断点，不允许跨断点连接路径。
- `GraphRenderer`：Compose Canvas 只消费采样路径和坐标变换，不在每一帧重新解析表达式或运行昂贵求解。

重点处理：

- 分母为零、根号内负数、对数非正等定义域外区域；
- 垂直渐近线附近的巨大数值和路径断裂；
- 可去间断点与原式定义域空洞；
- 振荡 / 高频区域采样不足；
- 视口边缘、超大 / 超小数值、数值溢出；
- 分段端点开闭与区间边界；
- 屏幕像素误差、坐标单位和函数值精度。

### 4.4 图像交互

首版必须具备：

- 平移、双指缩放、双击重置视口。
- 自适应坐标轴、主 / 次刻度和网格；刻度间隔优先选择易读数值。
- 单指探针 / 十字光标，显示当前 x、f(x)，定义域外要显示“无定义”而不是画出错误点。
- 多函数图例、颜色区分、单条显示 / 隐藏。
- 常用视口预设、自动适配、输入指定 x 范围。
- 数值表：显示选定区间的 x 与 f(x)，步长可设置。
- 可编辑参数滑块；拖动时局部更新采样，不重置用户视口。
- 断点 / 极点标记、根和极值标记必须以已验证算法为来源；不确定时明确标注“数值估计”。

### 4.5 图像精度验收

- 已知解析图像黄金样例覆盖：直线、抛物线、三次曲线、反比例、带孔函数、竖直渐近线、根式、对数、三角与分段函数。
- 检查断点两侧不被错误连线，图像缩放与平移不会改变采样语义。
- 对已知根 / 极值 / 交点使用独立数值或解析方法核验残差。
- 同一表达式在数值表、光标探针、图像和 solver 中返回一致的函数值及定义域结论。
- 以不同屏幕密度、窄屏、横屏、系统字体放大与低性能档测试流畅度和可读性。

## 5. AI 复杂题分析与解题体验

### 5.1 AI 的触发与定位

AI 不参与简单运算。复杂题能力由本地题型识别和求解器状态决定：

- 简单题：只显示本地结果，无 AI 自动提示。
- 复杂但本地可解：展示「AI 分析思路 / 独立核验」可选入口。
- 本地部分可解：显示本地完成部分，并让 AI 接续未覆盖部分。
- 本地暂不支持：显示「AI 尝试解题」，明确结果需要验证。
- 用户主动追问：带入当前题目快照与已展示步骤，继续讨论。

AI 分析和 AI 解题可以分开：

- **分析：** 拆解题型、关键条件、知识点和解题思路，检查已有解答。
- **解题：** 给完整分步过程、关键公式、代入、推导、最终答案和检验。
- **扩展：** 多方法、参数讨论、变式题、图像解释或关联知识点。

### 5.2 题目上下文

AI 接收 `QuestionDocument` 的安全摘要，而不是整页 UI 或所有历史：

- 学科 / 年级范围 / 题型标签；
- 用户原始题干及公式块；
- 本地 solver 已得结果、已完成步骤和明确的 Unsupported 项；
- 定义域、单位、参数、图像视口和用户选中内容；
- 用户要求：只分析思路、完整解题、检查自己的答案或多解法。

请求必须绑定不可变题目 revision。用户改动题目后，旧 AI 回答标记为“基于上一版题目”，不得混到新题目结果中。

### 5.3 AI 解题输出

复杂题默认结构：

1. 核心结论 / 最终答案；
2. 题型识别与已知条件；
3. 关键知识点和解题思路；
4. 分步骤推导（每个关键等式有依据）；
5. 答案检验（代回原题、单位、定义域、范围、守恒等）；
6. 易错点与必要的条件讨论；
7. 需要时给第二种思路或关联知识点。

面向高中生，按题目要求控制过程长度。用户说“只要必要过程”时不机械输出长篇模板。AI 对不确定题目应指出歧义、列出条件分支，不把估计根说成精确解。

### 5.4 AI 与本地解答核验

- 本地结果和 AI 答案各自保留来源标签。
- 已有解析 solver 时，以代数代回、定义域、残差、单位或守恒检查 AI 的可核验结论。
- 函数图像仍由本地引擎画；AI 可以解释曲线特征，不能提供像素路径。
- AI 生成的公式必须经过公式解析 / 安全渲染，不能执行模型生成的代码或脚本。
- 如果 AI 过程出现不等式方向、定义域、分母零点、单位或化学守恒错误，显示核验失败提示，不静默标记正确。
- 暂无本地验证器的证明 / 文字推理，标注“AI 推导，尚无自动证明器验证”。

### 7.1 执行顺序与并行边界

- 当前第一优先级仍是已在进行的纯 Kotlin 数学核心 C4.2.2 / C4.2.3，不开始大规模 UI。
- `QuestionDocument` 和输入法规划可以先做独立设计审查；编码时先做文档模型，再做键盘。
- 函数图像必须等表达式求值、函数定义域和基础函数分析稳定后实施。
- AI 的复杂度判断可以先做接口设计；真正发送请求之前，必须先完成 Worker 原生安全认证。
- AI UI 不得成为本地 solver 的依赖；即使 Worker 不可用，所有已实现的本地题型仍能使用。
- 数学、化学、物理键盘共用编辑器与符号搜索，但每个学科使用独立模板和 parser adapter。
- 每一小步独立 commit、同步文档、跑 JUnit / Android 构建；失败只修当前错误，不将大块功能堆到同一次提交。

## 8. 性能、隐私与可靠性约束

### 输入与键盘

- 高频按键不触发整个页面昂贵重组；光标、文档和键盘状态分离。
- 模板插入与撤销操作必须是原子编辑事务。
- 不因输入法动画、键盘页切换或系统键盘弹出丢失字符、光标和滚动位置。
- 符号字体 / 渲染缺字时显示可编辑原文或明确占位，不替换成空白字符。

### 函数图像

- 解析和采样放后台线程 / 可取消任务；拖动时限制采样预算并使用渐进精度。
- 视口变化只使当前图像采样失效，不让整个计算页重建。
- 缓存键包含函数表达式、参数、视口和密度；输入变化立即失效。
- 低端设备提供采样质量档位，但不改变数学结果定义或隐藏断点。

### AI 与隐私

- 仅复杂题且用户明确确认后联网。
- 显示将发送的题目和上下文摘要；用户可以删减敏感信息。
- Worker 持有上游 API Key；APK 不含 API Key。
- 服务器日志只保留必要调用元数据，不保存完整题目 / 回答，除非未来有明确的用户授权与安全设计。
- AI 断网、限流或服务异常不影响本地 solver 和图像。
- 普通计算、函数绘图和键盘输入默认离线可用；网络开关状态清楚可见。

## 9. 总验收清单

### 产品策略

- [ ] 简单算式输入、求值、重复使用时不出现自动 AI 请求。
- [ ] 简单任务没有显眼 AI 推销入口。
- [ ] 本地不支持或复杂综合题会展示明确的 AI 可选操作。
- [ ] 用户发送前看得到实际题目和上下文摘要。
- [ ] AI 输出与本地结果分开，状态与可信度说明清楚。

### 输入

- [ ] 可完整输入普通中文 / 英文题干、数字、标点与多行文字。
- [ ] 专用键盘覆盖高中常用数学 / 几何 / 物理 / 化学符号和模板。
- [ ] 搜索任意符号时能找到已收录符号；不在符号库时可原样输入 / 粘贴。
- [ ] 模板支持嵌套编辑、撤销 / 重做、选区与光标移动。
- [ ] 系统键盘切换、窄屏和横屏不导致输入丢失。

### 函数图像

- [ ] 连续区间、断点、极点、可去间断点和定义域外区域处理正确。
- [ ] 视口缩放 / 平移 / 重置、探针、数值表和参数滑块可用。
- [ ] 图像、数值表和本地求值结果一致。
- [ ] 不在断点跨越连线，不将估计值伪装成解析解。
- [ ] 图像有明确角度单位、坐标刻度和数值精度。

### AI 解题

- [ ] 多种高中题型可传入正确题目上下文。
- [ ] 输出核心答案、必要步骤、检验和不确定性。
- [ ] 对条件不完整的题目能明确提出缺失信息或列条件分支。
- [ ] 用户修改题目后旧回答不会套用到新题目。
- [ ] AI 失败、取消或超时后状态完全恢复，本地结果保留。
